# מחולל דוחות מעבדה (Lab Report Generator)

אפליקציית Windows מקומית ליצירת דוחות מעבדה הנדסית בעברית (Word `.docx`),
בהתאם למבנה, לניסוח ולעימוד של דוחות "המעבדה ההנדסית המרכזית בע"מ" (מקבוצת
המכון לחקר הכשל). המשתמש מזין כמה פרטים קצרים ומצרף תמונות; ה-AI מנסח את
הטקסט בעברית בסגנון הקיים, המשתמש בודק ועורך, והמערכת בונה את קובץ ה-Word
הסופי מתוך התבנית הרשמית.

## מבנה הפרויקט

| קובץ/תיקייה | תפקיד |
|---|---|
| `app.py` | ממשק המשתמש (Flet), בעברית ו-RTL מלא. |
| `report_builder.py` | בניית ה-`.docx` הסופי מהתבנית (docxtpl + python-docx). |
| `ai_service.py` | שכבת AI עצמאית מספק, מייצרת JSON מובנה בעברית בלבד. |
| `photo_service.py` | אימות/שינוי גודל/תצוגה מקדימה/הצעת חיתוך לתמונות. |
| `template_prep.py` | "קומפילציה" חד-פעמית של התבנית הריקה לגרסה עם תגי Jinja - **אף פעם לא נוגע בקובץ המקורי**; התוצר נשמר תחת `build/templates/`. |
| `config.py` | נתיבים והגדרות (נטענות גם מקובץ `.env`). |
| `prompts/report_prompt.txt` | הנחיות הכתיבה שנשלחות ל-AI. |
| `data/style_guide.md` | מדריך סגנון שחולץ מהדוחות לדוגמה. |
| `templates/` | **קבצי המקור המקוריים בלבד** - התבנית הריקה ודוחות לדוגמה. לא נכתב ולא ישונה קובץ בתיקייה זו על ידי האפליקציה. |
| `tests/` | בדיקות יחידה (pytest). |

## התקנה

1. Python 3.12 ומעלה.
2. סביבה וירטואלית (מומלץ):
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```
3. התקנת חבילות:
   ```bash
   pip install -r requirements.txt
   ```
4. יצירת קובץ הגדרות אישי:
   ```bash
   copy .env.example .env
   ```
   ולאחר מכן למלא ב-`.env` את `AI_API_KEY` (ואת `AI_PROVIDER`, אם רוצים
   ספק אחר מ-`anthropic`). **אין להעלות את `.env` ל-Git.**

## הרצה

```bash
python app.py
```

בהרצה הראשונה תיבנה אוטומטית (חד-פעמית) גרסת עבודה של התבנית עם תגי Jinja,
תחת `build/templates/` - הקובץ המקורי ב-`templates/` לעולם לא נכתב.

## זרימת העבודה

1. מילוי פרטי הדוח (מספר בדיקה, תאריך, לקוח, נושא וכו') והעלאת תמונות.
2. לחיצה על "צור טיוטת טקסט עם AI" - ה-AI מנסח את הפרקים "כללי", "ממצאים"
   ו"דיון ומסקנות" בעברית, על בסיס העובדות שהוזנו בלבד (הוא לעולם לא ממציא
   ממצאים, מדידות או מסקנות).
3. בדיקה ועריכה חופשית של הטקסט שנוצר.
4. סידור התמונות (ניתן לגרור לסדר מחדש), הוספת כיתוב לכל תמונה, ואישור/דחיית
   הצעת חיתוך (אם קיימת).
5. לחיצה על "צור דוח Word" - נשמר קובץ בשם `<מספר>_<תאריך>_<לקוח>.docx`
   בתיקיית `reports/`, ותיקיית הפלט נפתחת אוטומטית.

## הפרדה בין ספק ה-AI לפורמט Word

ה-AI **אף פעם** לא מתבקש לייצר עיצוב Word - הוא רק מחזיר JSON עם רשימות
פסקאות בעברית. כל הפורמט (RTL, יישור, גופנים, כותרות) מגיע מהתבנית המקורית
עצמה: `report_builder.py` רק מכניס טקסט לתוך פסקאות שכבר קיימות בתבנית.

## מגבלות ידועות והחלטות עיצוב

- **פריסת תמונות**: בדוחות המקוריים התמונות ממוקמות ידנית ב"ציור חופשי"
  (floating images) עם כיתובים מסכמים למספר תמונות יחד. docxtpl/python-docx
  אינם יכולים לשחזר זאת באופן אמין. הפתרון: טבלת תמונות (grid) שנבנית
  אוטומטית, כיתוב אחד לכל תמונה, ממוספר "תמונה N".
- **מספר עמודים**: השדה "מספר עמודים" בטבלת הפתיחה הוא הערכה שניתנת לעריכה
  ולא ספירה מדויקת (python-docx אינו מבצע עימוד אמיתי).
- **מדריך הסגנון** (`data/style_guide.md`) נבנה מ-8 דוחות לדוגמה בלבד -
  פחות מ-15–25 המומלצים. מומלץ להוסיף עוד דוגמאות ולעדכן את המדריך.
- דוחות הדוגמה נמצאים בפועל תחת `templates/crane_refernces/`,
  `templates/chassis_references/` ו-`templates/actuator_refernces/`
  (ולא תחת `templates/reference_reports/`) - כך נשמרו קבצי המשתמש כפי
  שהם, ללא שינוי מבנה תיקיות.

## בדיקות

```bash
pytest
```

בודקות: בניית הדוח מהתבנית, כיוון RTL בטקסט ובכיתובי תמונות, עיבוד תמונות
(אימות/שינוי גודל/חיתוך), ואימות תגובות ה-AI (סכימת pydantic, ניסיונות חוזרים,
טיפול בשגיאות).

## הוספת ספק AI נוסף

`ai_service.py` בנוי סביב מחלקת בסיס מופשטת `AIService`. ה-V1 כולל שני
מימושים (`anthropic`, `openai`); להוספת ספק נוסף יש ליצור מחלקה היורשת
מ-`_RetryingAIService`, לממש את `_call_model`, ולהוסיף אותה למילון
`_PROVIDERS`.
